# SmartSchool — запуск презентации

Локальная демонстрация: backend в Docker (`../SmartSchool`, API на `http://localhost`),
frontend — production-сборка на `http://localhost:3002`. Файлы `.env` / `.env.local` не меняются:
адрес API передаётся только на время сборки.

## Запуск (PowerShell)

1. Запустить Docker Desktop и дождаться статуса «Engine running».
2. Backend:

```powershell
cd ..\SmartSchool
docker compose start
curl.exe http://localhost/health
```

`curl` должен вернуть `{"status":"ok"}`.
Используйте `start`, а не `up`: `up` может пересоздать контейнеры, и API потеряет доступ к существующей базе.
`docker compose up -d` нужен только при самом первом запуске, когда контейнеров ещё нет.

3. Frontend (сборка 1–2 минуты, затем запуск):

```powershell
cd ..\smart-school
$env:NEXT_PUBLIC_API_URL = "http://localhost"
npm run build
npx next start -p 3002
```

4. Открыть <http://localhost:3002>. Окно с `next start` не закрывать до конца презентации.

Если сборка уже сделана этими командами, при повторном запуске достаточно `npx next start -p 3002`.

## Остановка

1. В окне frontend нажать `Ctrl+C`.
2. Backend (контейнеры и данные базы сохраняются):

```powershell
cd ..\SmartSchool
docker compose stop
```

Не используйте `docker compose down -v`: флаг `-v` удаляет базу.

## Возможные проблемы

| Симптом | Причина и решение |
|---|---|
| «Не удалось связаться с сервером» при входе | Backend не запущен: `docker compose start`, проверить `curl.exe http://localhost/health` |
| `/health` не отвечает, в `docker compose logs api` — `password authentication failed` | Контейнеры пересозданы с другим паролем БД. Не выполнять `down -v`; написать разработчику backend |
| Неверный ИНН или пароль у demo-аккаунта | Пароль менялся на репетиции. Ученику пароль сбрасывает директор («Ученики» → «Сбросить пароль»); для остальных ролей в интерфейсе сброса нет. На репетиции не меняйте пароли demo-аккаунтов |
| Excel-импорт показывает «Пользователь с таким ИНН уже есть» | Файл `demo-students-import.xlsx` уже импортировали на репетиции — это нормально, валидация работает. Для чистого показа поменяйте ИНН в файле |
| Порт 3002 занят | Закрыть предыдущее окно `next start` или выбрать другой порт: `npx next start -p 3003` |
| Данные уходят на удалённый сервер | Сборка сделана без `$env:NEXT_PUBLIC_API_URL = "http://localhost"` — пересобрать по шагу 3 |
| Во вкладке старая иконка | Кэш браузера: `Ctrl+F5` |

## Деплой на Vercel

Сайт на Vercel открывается по `https`, а backend доступен только по `http`.
Браузер блокирует такие запросы (mixed content), поэтому фронт обращается к API
через свой домен: `/api/...` → `src/proxy.ts` пересылает запрос на backend.

Environment Variables в Vercel (Production и Preview):

| Переменная | Значение | Зачем |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | `/api` | фронт ходит на свой домен |
| `BACKEND_URL` | `http://<адрес backend>` (без `/` на конце) | куда прокси пересылает запросы |

`NEXT_PUBLIC_*` встраиваются при сборке — после изменения переменных нужен **Redeploy**.
Когда у backend появится свой домен с HTTPS, можно указать его прямо в `NEXT_PUBLIC_API_URL`.
