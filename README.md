# 🎓 SmartSchool

### Цифровая образовательная платформа для школ Кыргызстана

SmartSchool — современная веб-платформа, предназначенная для цифровизации школьных процессов, повышения прозрачности образовательного процесса и улучшения взаимодействия между учениками, родителями, учителями и администрацией школы.

Платформа объединяет электронный журнал, домашние задания, посещаемость, аналитику успеваемости, рейтинги и инструменты управления школой в единой системе.

## 📖 О проекте

SmartSchool разрабатывается как единая цифровая образовательная среда для школ Кыргызстана.

Основная задача проекта — сделать школьные процессы более удобными, понятными и доступными для всех участников образовательного процесса.

Платформа ориентирована на пять основных категорий пользователей:

- Директора и завучи.
- Учителя.
- Классные руководители.
- Ученики.
- Родители.

**Основные принципы проекта:**

- Простота использования.
- Понятный интерфейс.
- Доступность с любых устройств.
- Безопасность персональных данных.
- Удобное взаимодействие между участниками.
- Единая система школьной информации.
- Поддержка кыргызского и русского языков.

## 🏗 Архитектура Frontend

Frontend SmartSchool построен на Next.js App Router.

Проект использует простую централизованную архитектуру с разделением ответственности между страницами, компонентами, API-запросами, hooks и общими настройками.

Главные архитектурные принципы:

1. Понятная структура проекта.
2. Минимум ненужных абстракций.
3. Повторное использование компонентов.
4. Разделение UI и API-логики.
5. Единый подход к написанию кода.
6. Удобство совместной разработки.

### Структура проекта

```text
src/
├── apis/
│
├── app/
│
├── components/
│   ├── layout/
│   ├── pages/
│   ├── ui/
│   └── widgets/
│
├── hooks/
│
└── lib/
```

### Назначение директорий

| Директория            | Ответственность                      |
| --------------------- | ------------------------------------ |
| `apis/`               | API-функции и типы запросов          |
| `app/`                | Маршруты и layouts Next.js           |
| `components/layout/`  | Sidebar, Header, Navigation          |
| `components/pages/`   | Компоненты страниц                   |
| `components/ui/`      | Переиспользуемые UI-компоненты       |
| `components/widgets/` | Самостоятельные функциональные блоки |
| `hooks/`              | React hooks и TanStack Query hooks   |
| `lib/`                | Axios, QueryClient и общие утилиты   |

Архитектура является утвержденной основой проекта. Новые архитектурные директории создаются только после согласования команды.

## ⚙️ Начало работы

### Требования

Перед началом разработки необходимо установить:

- Node.js — поддерживаемую проектом LTS-версию.
- npm.
- Git.

### 1. Клонирование проекта

```bash
git clone <REPOSITORY_URL>
```

### 2. Переход в директорию

```bash
cd smart-school
```

### 3. Установка зависимостей

```bash
npm install
```

### 4. Настройка переменных окружения

Создай файл `.env.local` в корне проекта.

Заполни необходимые переменные согласно фактической конфигурации проекта.

### 5. Запуск проекта

```bash
npm run dev
```

После запуска открой:

```text
http://localhost:3000
```

**Важно:** команды и переменные окружения необходимо сверять с актуальными `package.json` и конфигурацией проекта.

## 🔐 Переменные окружения

Пример оформления:

```env
NEXT_PUBLIC_API_URL=
```

Необходимо учитывать:

- Не публиковать реальные секреты.
- Не добавлять `.env.local` в Git.
- Не хранить пароли и приватные ключи в исходном коде.
- Публичные переменные окружения использовать только для данных, которые допустимо раскрывать браузеру.

Полный перечень переменных должен соответствовать реальной конфигурации Backend и Frontend.

## 📏 Основные соглашения

### Code Style

- Использовать TypeScript.
- Предпочитать простые и понятные функции.
- Не усложнять архитектуру без необходимости.
- Использовать понятные названия переменных и компонентов.
- Избегать `any`.
- Не создавать ненужные файлы и директории.
- Не дублировать существующий функционал.

### Components

- Использовать функциональные React-компоненты.
- Переиспользовать существующие UI-компоненты.
- Использовать shadcn/ui там, где это оправдано.
- Разделять компоненты по их ответственности.

### Styling

- Использовать SCSS Modules.
- Избегать ненужных глобальных стилей.
- Поддерживать единый дизайн.
- Учитывать обе темы оформления.

### API

- Использовать общий Axios instance.
- Размещать API-функции в `src/apis/`.
- Использовать TanStack Query.
- Обрабатывать ошибки и состояния загрузки.

## 👨‍💻 Командная разработка

Frontend-разработка ведется двумя разработчиками.

Для сохранения единого подхода команда использует общие правила архитектуры, именования и написания кода.

### Основные правила

- Не изменять архитектуру самостоятельно.
- Не создавать лишние папки.
- Перед созданием компонента проверять существующие.
- Не дублировать API-функции.
- Согласовывать крупные изменения.
- Не изменять чужую работу без необходимости.
- Поддерживать понятный и единый стиль кода.
